# 제품 spec — 사용자 흐름

AirPods를 착용하고 작업하다 고개를 돌리거나 자리를 벗어나면 Mac 화면을 흐리게 가리는 앱임. 메뉴 막대에서 상태를 보고 보호를 관리함. **승인된 행동과 아래의 추가 제안을 구분하며, 구현 방법은 자율 위임 범위에서 결정함.**

현재 상태: 화면 효과·방향 대응·메뉴 구성·가림 중 관리 메뉴 유지 승인됨. 초기 보정에서 블러 시작 각도를 설정하는 요구가 추가됐음. 시작·복귀·실패·데이터의 연결 흐름은 아래 P1~P3 추천안으로 최종 결정 중임. 이동량 추정과 기립 대안을 실험하는 앱을 구현 중임. 화면 기록 권한의 메모리 블러 처리·무저장·무전송 용도는 후속 승인됐음. 실제 감지 품질은 검증 전임.

## 이번에 함께 닫을 범위

이번 결정은 첫 개인용 버전의 하루 사용 흐름임. 기존 승인을 다시 묻지 않고 새 행동을 세 묶음으로 제안함. 출처는 아래 승인 기록이며, 출처가 메인 제안인 문장은 승인 전임.

| 묶음 | 결정할 사용자 경험 | 아직 승인되지 않은 핵심 |
| --- | --- | --- |
| P1 시작과 관리 | 실행→연결 확인→화면별 정면·블러 시작 각도 맞추기→사용자가 보호 켜기 | 앱을 다시 열면 보호 꺼짐, 같은 Mac에서 설정은 기억, 화면 배치가 달라지면 다시 보정 |
| P2 작업과 복귀 | 정상 회전은 연속 블러, 신호 소실은 기본 해제·선택적 유지 | 회전은 자동 복귀, 신호 소실은 기본 해제 또는 전체 블러 유지 후 수동 재개 |
| P3 범위와 입력 | 현재 좌우 외장 화면에서 AirPods로 로컬 동작 | 카메라·계정·서버 없는 범위 제안. 화면 기록의 메모리 블러 용도는 아래 후속 승인으로 갱신 |

설정값·감지 계산·렌더링 방법은 질문 목록이 아님. 구현자가 후보를 만들고 실제 동작으로 사용자에게 판단 근거를 제공함. 숫자는 실험으로 조정하되 사용자에게 제공할 행동·허용할 노출·권한을 몰래 바꾸지 않음.

## 하루 사용 흐름

```text
앱 실행·메뉴 확인 → AirPods 연결과 기준 준비 → 보호 켜기 → 고개에 따른 부분 블러
                                                        ↓
                                        신호 소실 시 기본 해제·옵션으로 전체 블러 유지
                                                        ↓
                                        복귀·입력 정상 확인 후 재개
```

### 1. 처음 실행하고 보호를 준비함 — P1 제안

앱을 실행하면 메뉴 막대 아이콘이 나타나고 보호는 꺼진 상태임. AirPods 연결·감지 가능 상태를 확인하고, 필요한 권한을 허용하지 않았다면 무엇을 허용해야 하는지 설명함. 연결이나 권한이 없으면 보호를 켤 수 없으며 준비되지 않은 상태를 ‘보호 중’이라고 표시하지 않음.

처음에는 왼쪽·오른쪽 화면을 각각 정면으로 보며 기준을 맞추고 **블러를 시작할 각도도 초기 설정에서 지정함**. 이는 후속 사용자 요구임. ‘정면 기준’은 화면을 바라보는 머리 방향이고 ‘시작 각도’는 그 방향에서 얼마나 돌렸을 때 흐리기 시작할지의 기준임. 시작 각도는 최대 블러에 도달하는 각도나 애니메이션 속도와 다름.

추천 조작은 화면 정면을 확인한 뒤 직접 고개를 돌리며 현재 각도와 블러 미리보기를 보고 시작 각도를 조절하는 것임. 설정한 범위 안에서는 선명하고 범위를 넘어가면 D3 방향대로 블러가 연속적으로 강해지는 흐름임. 화면별 값·좌우 값을 따로 둘지와 구체 입력 방식은 시안에서 검토하며 같은 요구를 별도 ‘민감도’ 설정으로 중복시키지 않음. 준비가 끝나도 사용자가 보호 켜기를 선택해야 자동 블러가 시작되는 것은 기존 P1 제안임.

추천 이유는 실행·재연결만으로 갑자기 화면이 가려지는 일을 줄이기 위함임. 실행하자마자 보호되는 것이 더 중요하면 자동 시작이 대안이지만, 의도하지 않은 가림과 권한 오류 시 동작까지 함께 정해야 함.

### 2. 작업하면서 고개를 돌림 — D3 승인된 효과

화면 내용·버튼·창 위치는 그대로 있고 블러 강도와 경계가 고개 방향에 따라 연속 변화함. 아래 방향은 **각 모니터의 정면 기준**임. 모니터 사이를 보는 정상 회전을 자리 이탈로 취급하지 않는 것을 P2의 수용 조건으로 제안함.

### D3. 어느 화면을 어떻게 가리는가

| 해당 화면 기준의 고개 방향 | 승인된 화면 결과 |
| --- | --- |
| 정면 | 해당 화면 전체가 선명함 |
| 오른쪽으로 시작 각도를 넘김 | 왼쪽부터 강하게 흐려지고 오른쪽은 상대적으로 선명하게 남음 |
| 왼쪽으로 시작 각도를 넘김 | 오른쪽부터 강하게 흐려지고 왼쪽은 상대적으로 선명하게 남음 |

좌우 외장 모니터 각각에 적용함. 축 가까운 쪽보다 먼 쪽이 더 강하게 흐려지는 분포와 책장을 넘기는 듯한 부드러운 변화가 시각 기준임. 화면 내부의 딱딱한 경계나 선명한 원형 구멍으로 임의 대체하지 않음.

### 3. 화면으로 다시 고개를 돌림 — P2 제안

자리에 있고 입력이 정상인 동안에는 고개를 각 모니터의 정면으로 되돌리면 그 화면이 부드럽게 선명해짐. 짧은 흔들림에 번쩍거리지 않도록 조정함. 어느 정도의 움직임을 무시하고 얼마나 빨리 따라오는지는 실험에서 후보를 비교함.

회전 중에도 화면 작업을 계속할 수 있게 하는 흐름임. 부분 블러가 있다고 매번 버튼을 눌러 해제할 필요는 없음. 아래의 자리 이탈·신호 소실로 가린 경우에는 이 자동 복귀를 적용하지 않는 안임.

### 4. 자리를 벗어나거나 감지가 끊김 — P2 제안

자리 이탈 징후를 감지하면 보호 대상 화면을 전체 블러 처리함. AirPods 탈착·연결 전환·권한 철회 등으로 감지할 수 없을 때도 전체 블러를 적용하거나 유지하고 메뉴에 이유를 표시함. 관리 메뉴와 메뉴 막대는 계속 사용할 수 있음.

사용자는 ‘자리 이탈 시에도 위치를 감지해 연속적인 블러가 가능한지’를 질문했음. **실제 이동 거리·위치에 따라 블러 강도가 달라지는 것**과 **이탈 감지 후 일정 시간에 걸쳐 부드럽게 전체 블러로 전환하는 것**은 다른 행동임. 전자는 위치 추정의 품질 검증이 필요하며 아직 지원으로 확정하지 않음. 후자는 거리 측정 없이도 시각 실험이 가능하지만 이탈 판단 정확도와 전환 중 노출 시간이 별도 문제임.

현재 추천 후보는 AirPods의 이탈 징후를 검증하고, 판정 후 현재 블러 상태에서 전체 블러까지 부드럽게 전환하는 것임. 위치 비례가 핵심이면 별도 위치 근거를 조사한 뒤 결정함. 이 추천을 위치 감지 요구의 승인된 대체로 취급하지 않음. 신호 소실은 이동 거리로 해석하지 않으며 위치 기반 자동 복귀까지 승인된 것은 아님. 기술적 가능 범위와 한계는 [타당성 조사](feasibility.md#자리-이탈과-연속-블러의-가능-범위)가 소유함.

자세를 바꾸는 것과 자리에서 일어나는 것은 달라야 함. AirPods만으로 이를 구별할 수 있는지는 [기술 타당성 조사](feasibility.md)의 검증 과제이며, Bluetooth 연결 여부만으로 이탈을 판정했다고 주장하지 않음.

가림 우선 추천은 감지 불능 상태에서 내용이 노출되는 것을 줄이려는 선택임. 반대급부는 일시적인 끊김에도 작업이 가려질 수 있다는 것임. 작업 연속성이 더 중요하면 화면을 그대로 두고 경고하는 대안이 있으나 감지 불능 동안의 노출을 허용하게 됨.

### 5. 자리로 돌아와 다시 사용함 — P2 제안

이탈·신호 소실 뒤에는 AirPods가 연결되거나 정면 자세가 잡혔다는 이유만으로 화면을 열지 않음. 입력이 정상이고 기준이 유효해지면 메뉴에서 ‘보호 재개’를 선택해 고개에 따른 부분 블러로 돌아가는 안임. 연결은 복구됐지만 아직 자리에 돌아오지 않은 상황에서의 잘못된 해제를 줄이기 위한 선택이며 복귀 때 클릭 한 번이 필요함.

감지 불능 상태에서도 승인된 ‘보호 끄기’는 사용 가능함. 이 조작은 가림을 해제하고 자동 보호를 중지하는 뜻임. 보호를 끈 이후에는 다시 켜기 전까지 연결 복구나 머리 움직임으로 가리지 않음.

### 6. 설정을 조절하거나 보정을 다시 함 — P1 제안

블러 시작 각도·강도·전환 속도를 메뉴의 설정에서 조절하는 안임. 초기 설정의 시작 각도를 여기서 다시 바꿀 수 있도록 같은 값을 사용함. 기존 메뉴 제안의 ‘민감도’와 시작 각도를 같은 목적의 독립 값 두 개로 만들지 않음. 변경 효과를 확인하고 자신에게 맞게 조절할 수 있게 하며, 구체 조절 범위·기본값은 실제 화면을 보고 정함.

같은 Mac에서 앱을 다시 실행하면 설정과 유효한 화면별 기준을 기억하는 안임. 매번 같은 값을 다시 맞추지 않기 위함임. 앱 재실행 시 보호 자체는 꺼짐으로 시작함. 기기를 바꾸거나 앱을 삭제한 뒤의 복원·계정 동기화는 첫 범위에 포함하지 않음.

화면 구성이 달라지거나 잠자기에서 돌아와 기준을 신뢰할 수 없으면 재확인이 필요함을 표시함. 보호 중이라면 기존 대상 화면의 가림은 유지하고 새 화면은 준비 전임을 알림. 새 화면까지 보호된 것처럼 표시하지 않음. 사용자가 보호를 끄거나 새 구성을 확인하고 재개할 수 있음. 보호 중 다시 보정하는 조작은 자동 변화를 멈추고 가림을 유지한 상태에서 시작하는 안임.

사람·모니터의 물리적 위치 변화까지 자동으로 알 수 있다고 약속하지 않음. 표시와 실제 방향이 어긋나면 사용자가 메뉴에서 기준을 다시 맞춤.

### 7. 끄거나 종료함 — D7 승인된 관리

### D7. 메뉴 막대에서 관리

메뉴 막대에서 상태 확인·보호 켜기/끄기·모니터 기준 맞추기·설정·종료를 제공함. 설정 항목은 블러 강도·반응 민감도·전환 속도임. 보호를 끄거나 앱을 종료하면 현재 가림도 해제함. 종료 후에는 자동 보호를 제공하지 않음.

최초 승인에서는 메뉴 막대와 관리 UI를 선명하게 유지했음. 이후 노치 좌우 보호 요청에 따라 메뉴 막대는 블러 대상에 포함하고, 펼친 관리 메뉴와 설정 UI의 접근을 유지함. 실제 메뉴 배치·문구·아이콘은 승인된 흐름을 보여주는 시안으로 검토함.

전체 화면·메뉴 막대 자동 숨김에서도 보호 끄기에 도달할 수 있는지 확인해야 함. 메뉴 접근이 안 되는 조합을 지원 완료라고 표시하지 않음. 별도 긴급 단축키가 필요하면 조작을 제안하고 결정함. Dock 아이콘·로그인 자동 실행은 메뉴 막대 승인에 포함되지 않으며 첫 필수 흐름 이후로 보류함.

## P3 — 사용 범위와 데이터 제안

첫 대상은 현재 MacBook Pro와 AirPods Pro, 좌우 외장 화면 조합임. 상세 기기·OS의 관측은 [실제 환경](feasibility.md#실제-환경-확인)이 소유함. 내장 화면을 추가한 구성·다른 기기는 별도 지원 검증 대상임.

추천 용도는 같은 공간의 사람이 화면 내용을 쉽게 읽지 못하게 돕는 것임. OS 잠금·인증·화면 공유/녹화 결과 차단은 첫 범위에 넣지 않음. 계정 접근 차단이나 원격 시청자에 대한 보호가 목적이면 별도 흐름을 정해야 함. 블러만으로 내용을 충분히 가리지 못하면 결과를 공개하고 가림 방식·지원 범위를 다시 결정함.

AirPods로 판단하고 처리는 Mac 안에서 끝내는 안을 추천함. 카메라·마이크·계정·서버를 추가하지 않고, 화면 내용과 원시 센서·사용 이력을 파일로 남기거나 외부로 보내지 않음. 기억할 것은 P1에서 정한 사용자 설정과 기준뿐임. 설정을 보존하는 방법은 구현자가 결정함.

motion 이용 권한은 시작 흐름에서 용도와 함께 요청함. 화면 녹화·접근성 등 추가 권한이 기술적으로 필요해지면 그 이유·허용되는 접근·대안을 먼저 설명하고 영향받는 경로만 보류함. 이미 승인된 범위의 내부 구현 선택은 다시 질문하지 않음.

## 구현자에게 맡긴 범위 — 사용자 위임

2026-09-14 사용자 ‘구현은 최적으로 자율적으로’ 지시에 따라 승인된 행동·권한·데이터 계약을 만족시키는 앱 구조, 언어·프레임워크 선택, 감지 계산, 화면 그리기, 동시성, 테스트와 빌드 설비를 구현자가 결정함. 중요한 선택의 이유와 검증 한계를 남기고 소스 작성 전에 AGENTS 배치 지도를 갱신함.

최적은 승인한 사용 흐름을 정확하게 제공하면서 지연·자원 사용·복잡도·유지 비용을 줄이는 방향임. 측정 없이 최적성을 입증했다고 표현하지 않음. 불필요한 의존성은 넣지 않으며 권한·외부 서비스·데이터 보관·제품 행동·공개 계약에 영향이 생기면 그 경계만 다시 결정함.

보호 정책·지원 범위·완료 조건은 구현 자율성으로 바꾸지 않음. 수치 후보를 시험하는 일과 사용자가 허용할 누락·오탐·노출을 정하는 일을 구분함. 이번 위임은 커밋·push·PR·배포 허가가 아님.

## 첫 구현 착수 — 2026-09-14 후속 결정

사용자가 ‘실험해보고 어려우면 기립만 감지해도 좋음. 이제 구현 시작하면 될까?’라고 요청했음. 이동량 기반 이탈을 먼저 실험하고 정확도가 부족하면 기립 감지로 좁히는 대안을 허용했음. 기립도 실제 판정 품질을 확인해야 하며 쉬운 직접 센서값이 있다고 가정하지 않음.

첫 구현 단위는 승인된 메뉴·정면/시작 각도 설정·부분 블러의 예제 화면과 AirPods 입력·이동량 계측임. 계측은 사람이 시작·중단하는 제한된 세션에서 메모리로 관측하며 실제 거리 정확도·기립 성공을 합성 입력 검사로 대신하지 않음. 아직 미정인 이탈/신호 소실 자동 보호와 설정 영속화는 이 단위에서 제품 기본값으로 확정하지 않음. 예제 화면의 각도·강도·속도 후보는 실험값이며 제품 합격 기준이 아님.

실제 데스크톱 가변 블러에 화면 기록 권한이 필요한 경우 메모리 처리 용도로 사용할 수 있는지 사용자에게 질문했음. 답변 전에는 해당 경로를 실행하지 않음. 이는 전체 개발 재승인 요청이 아니며 독립적인 앱·센서·예제 화면 구현은 진행함.

**화면 기록 권한 — 같은 날 후속 승인.** 사용자가 화면을 저장·외부 전송하지 않고 메모리에서 블러 처리하는 용도로 화면 기록 권한을 허용했음. 실제 데스크톱 블러 구현과 해당 OS 권한 요청을 진행 가능함. P3의 ‘화면 녹화 없이’ 제안 중 화면 접근 부분은 이 결정으로 갱신됐으며 기록 파일을 만드는 동작은 포함하지 않음.

**의존성 위임 — 같은 날 후속.** 외부 라이브러리가 필요하면 사용 가능하다고 사용자가 명시했음. 기능·권한·보관 계약을 유지하는 범위에서 정확도·성능·유지 비용의 이점으로 채택하며 무조건 의존성 0을 목표로 구현을 악화하지 않음.

## 실물 후속 요구 — 2026-09-14

사용자는 한 모니터가 완전히 가려진 뒤 고개를 더 돌려야 다음 모니터가 시작되는 간격을 부자연스럽다고 설명했음. 인접 화면의 전환이 겹쳐 이어지도록 개선함. 보호를 켜도 영상 위치와 실제 클릭 대상이 일치해야 함. 구체 경계 폭·강도 보간은 구현자가 실험하며 실물 결과로 확인함.

사용자가 연결 정도를 직접 조절해 자연스러운 값을 찾도록 요청했음. 실제 화면 보호 영역에 ‘모니터 연결 폭’을 제공하며 기본 25%, 0~50% 범위로 양쪽 가장자리의 연결 구간을 조절함. 0%는 독립 동작이며 보호 중 변경을 즉시 반영함. 다른 실험값과 같이 이번 실행에만 유지함.

기본값 후속 요청: 각 화면의 블러 시작 각도는 35°로 설정함. 블러 강도는 기존 슬라이더 범위 15~80의 1/4 지점인 31.25로 설정함. 연결 폭 기본값은 기존 25%를 유지함.

## 현재 파노라마 방식 — 사용자 후속 결정

이 절은 앞선 모니터별 정면 보정·독립 블러·가장자리 혼합 방식과 연결 폭의 의미를 대체함. 사용자가 하나의 연속된 시야, 실제 화면 폭 반영, 빈 간격까지 이어지는 가상 화면을 요청했고 폭과 간격을 cm로 입력하는 방식을 선택했음. 이어 책상 정면 한 번만 보정하는 방식으로 단순화했음.

사용 흐름은 책상 정면 보정 → 좌우 표시 영역의 가로 길이와 간격 입력 → 실제 보호 켜기임. 거리의 초기값은 사용자 추정 60cm, 정면 위치는 두 화면 사이 중심임. 두 값 모두 앱에서 수정할 수 있으며 정면 위치 이동은 그 중심에서 왼쪽 음수·오른쪽 양수 cm임. 실제 화면 폭은 아직 미확인이므로 초기 0에서 사용자가 입력함. 유효한 두 폭과 거리, 정면 보정, 신선한 입력이 준비되어야 보호를 시작함.

각 화면은 하나의 파노라마에서 자기 구간을 표시함. 빈 공간에도 같은 계산이 이어지며 거기에 실제 화면을 출력하지는 않음. 화면마다 따로 시작하거나 가장자리 결과를 평균내지 않음. 공통 시작 각도는 정면 시야에서 각 위치가 벗어난 각도의 기준이며 초기 35°임. 강도 기본값은 앞서 정한 값을 유지함.

App Store 호환성·외부 배포 승인을 의미하지 않음. 검증은 사용자 요청에 따라 내장 화면만 대상으로 하며 외장 작업 중 전역 화면 전환 입력을 보내지 않음. `--built-in-only`는 그 실행을 위한 진단 범위이고 기본 본체의 전체 화면 배치 설정은 유지함.

### 시스템 배치 초기화와 3D 클릭 선택 — 2026-09-15 승인

2026-11-12 배치 수정 화면 결정으로 3D 보기와 장면은 대체됨. 시스템 배치 초기값, 클릭 선택, 팔 길이 기본값은 유지함.

사용자가 시스템 디스플레이 배치를 3D 초기값으로 가져오는 제안과 3D 모니터 클릭 선택을 승인했음. 처음 배치를 열면 활성 화면의 논리 좌표에서 좌우·상하·정렬 관계를 가져오고 시스템 보고 물리 크기로 배치함. 논리 포인트 간격을 실제 cm로 해석하지 않으며 기존 간격·거리 초기값을 사용함. 거리·간격·수평 기울기는 시스템에서 알 수 없는 물리 보정값임. 이미 적용한 배치는 다시 열 때 유지하며, 기존 화면 구성 변경의 무효화 정책을 따름.

3D 모니터를 클릭하면 그 모니터가 선택되어 아래 설정과 선택 메뉴가 함께 바뀜. 선택 표시는 화면 내용의 블러를 바꾸지 않고 테두리로 구분함. 메뉴를 통한 선택도 유지함. 배치 변환은 설정용이며 실제 보호의 반복 계산에 3D 렌더링을 추가하지 않음.

## 앱 내 업데이트와 필수 업데이트 — 2026-11-11 사용자 결정

사용자가 강제 업데이트 추가를 지시하고 세 가지를 정했음.

| 결정 | 사용자 선택 | 반영 |
| --- | --- | --- |
| 강제 수준 | "설정 화면에서 막는 느낌 어때? 사용하는 사람 계속 사용하고" | 필수 판본이 있으면 설정 창과 배치 시트를 업데이트 안내로 덮고 조작을 막음. 메뉴 막대의 보호 켜기와 끄기, 이미 켜진 보호는 그대로 동작함 |
| 설치 방식 | Sparkle로 앱 안에서 설치 | 안내의 업데이트 버튼과 메뉴의 업데이트 확인이 Sparkle 표준 창을 열어 내려받기, 설치, 재실행을 함 |
| 배포 위치 | GitHub Release와 main의 appcast | DMG는 `philosophia301/privacy-with-airpod` Release에, 판본 목록은 저장소 main의 `appcast.xml`에 둠 |

필수 여부는 배포할 때 정함. appcast 항목에 "빌드 N 미만은 필수"를 표시하면 그보다 낮은 빌드의 앱이 설정 창을 막음. 표시가 없는 업데이트는 Sparkle의 일반 업데이트 안내만 받음. 한 번 정한 필수 기준은 다음 판본에도 이어짐.

네트워크 사용: 이 기능으로 앱이 처음 네트워크를 씀. 실행할 때와 하루 한 번 GitHub(raw.githubusercontent.com)에서 appcast를 받고, 사용자가 업데이트를 고르면 GitHub Release에서 DMG를 받음. 요청에는 Sparkle 기본 User-Agent(앱 이름과 버전)가 실림. 시스템 정보 전송(system profiling)은 켜지 않음. 화면 내용, 보정값, AirPods 입력은 보내지 않음.

실패 시 동작: 확인 실패, 오프라인, 서버 오류는 막지 않음(fail open). 한 번 필수로 판정된 뒤에는 이후 확인이 실패해도 그 실행에서는 막힌 상태를 유지하고, 새 확인에서 필수가 아니면 풂.

경계: 0.1.1 이하에는 업데이트 기능이 없으므로 업데이트 기능이 들어간 첫 판본은 사용자가 한 번 직접 설치해야 함. 구현과 배포 절차는 [개발 안내](development.md#앱-내-업데이트와-필수-업데이트--2026-11-11)가 소유함.

| 결정 | 사용자 선택 | 보이는 결과 |
| --- | --- | --- |
| 기억 범위 | 설정과 배치 | 가리기 탭의 시작 각도, 농도, 연결 폭, 반응 시간, 'AirPods를 벗으면' 선택, 화면 배치, 팔 길이를 같은 Mac에 기억함. 앱을 다시 열거나 업데이트로 재실행해도 값이 그대로임 |
| 정면 기준 | 기억하지 않음 | AirPods 입력을 다시 시작하면 각도 기준이 바뀌어 저장한 값이 맞지 않음. 다시 열면 정면 맞추기 한 번이 남음 |
| 재실행 보호 | 꺼진 채로 시작 | 끝낼 때 보호 중이었어도 다시 열면 꺼져 있음. 정면을 맞춘 뒤 사용자가 보호를 켬 |
| 화면 구성 | 모니터 조합별로 기억 | 연결된 모니터 조합마다 배치를 따로 기억함. 같은 조합이 다시 연결되면 배치를 자동으로 되살리고, 처음 보는 조합이면 배치를 다시 받음. 해상도나 배열만 바뀌어도 같은 조합이면 배치가 남음. 화면 구성이 바뀌면 보호를 끄고 정면 기준을 지우는 기존 정책은 그대로임 |
| 로그인 시 실행 | 스위치, 기본 꺼짐 | 설정 창에 '로그인할 때 열기' 스위치를 둠. 사용자가 켜야 macOS 로그인 항목에 등록됨 |

이유: 다시 열 때마다 같은 값을 맞추는 수고를 없애되, 실행만으로 화면이 가려지는 일은 만들지 않기 위함임. 저장은 이 Mac 안에만 하고 외부로 보내지 않음. 화면 내용, 원시 센서 값, 사용 이력은 저장하지 않음. 기기 사이 동기화와 앱 삭제 뒤 복원은 범위 밖임.

허용한 결과: 다시 열면 정면 맞추기는 매번 필요함. 같은 모니터 조합이라도 실제 책상 위 위치를 옮겼다면 저장된 배치가 맞지 않을 수 있으며, 사용자가 배치 수정으로 고침. macOS에서 화면 방향(가로, 세로)을 바꾼 모니터는 같은 조합이어도 배치를 다시 받음.

| 복귀 | 앉으면 바로 | 다시 앉는 동작을 감지하면 곧바로 고개를 따라가는 블러로 돌아감. 정면 기준은 그대로 씀. 앉기를 놓치면 가린 채로 남고, 메뉴나 설정 창의 '보호 재개'로 직접 돌아감 |

이유: 자리를 비운 동안 화면이 보이지 않게 하되, 앉아서 일하는 동안의 잦은 가림은 피하기 위함임. 일어선 뒤 3초를 기다려 물건 줍기나 기지개 같은 짧은 동작을 넘김. 걷기는 자리를 뜬 뚜렷한 신호라 기다리지 않음.

허용한 결과: 일어선 뒤 3초 동안은 화면이 고개를 따라가는 블러 상태로 남음. 일어서기를 놓치고 걷지도 않으면 가리지 않음. 다른 자리에 앉아도 앉기로 보고 돌아올 수 있음. 판정은 AirPods 움직임만 쓰며 실제 위치나 거리를 재지 않음. 판정 기준이 실측 전이라 실제 사용에서 놓침이나 잘못 가림이 있을 수 있음. 움직임 값은 판정에만 쓰고 저장하지 않음.
