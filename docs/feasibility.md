# 기술 타당성 — 문서 조사와 실물 확인의 경계

2026-09-14 Apple 공식 문서를 확인했음. **Mac에서 지원 헤드폰의 motion을 받는 공개 API는 있으나 이 앱의 감지·블러 동작은 실행하지 않았음.** 제품 정책은 [spec](spec.md)이 소유함.

## 실제 환경 확인

2026-09-14 사용자가 computer-use 확인을 허용했고 시스템 설정의 Bluetooth·디스플레이·일반→정보 화면을 열람했음. 설정값은 변경하지 않았음. 처음 조회는 `window_not_found`였고 시스템 설정을 연 뒤 관측 가능했음. 클릭 명령 자체는 synthetic/unverified였으며 후속 화면의 값으로 이동 결과를 확인했음.

| 항목 | 관측 | 근거·한계 |
| --- | --- | --- |
| AirPods | AirPods Pro, A2698, 연결됨, 버전 8B41 | Bluetooth 상세의 텍스트. motion sample 수신은 미검증 |
| Mac | MacBook Pro 16, 2024년 11월 모델, Apple M4 Pro | 일반→정보의 텍스트 |
| macOS | Tahoe 26.6.2 | 일반→정보의 텍스트, 사용자 제공 값과 일치 |
| 외장 화면 1 | BK550Y, 확장된 디스플레이, 1920×1080, 60Hz | 디스플레이에서 해당 화면을 선택한 텍스트 |
| 외장 화면 2 | 27MB35, 메인 디스플레이, 1920×1080, 60Hz | 디스플레이에서 해당 화면을 선택한 텍스트 |
| 물리 배치 | 좌우 외장 화면 사용 | 사용자 진술. 설정의 기기 선택 목록만으로 실제 좌우 순서·각도를 확정하지 않음 |

디스플레이 선택 화면에는 외장 두 대가 보였음. 내장 화면이 목록에 없다는 사실만으로 뚜껑 상태를 확정하지 않음. 일련번호·주변 Bluetooth 기기 정보·사용자 화면 내용은 프로젝트 문서에 보관하지 않음.

## 문서에서 확인한 사실

| 항목 | 확인 내용 | 근거 |
| --- | --- | --- |
| macOS 입력 경로 | `CMHeadphoneMotionManager`의 macOS 지원은 macOS 14부터 소개됨. 동적 머리 추적을 지원하는 오디오 제품에서 자세·가속도·회전 속도를 받음 | [WWDC23 Core Motion](https://developer.apple.com/videos/play/wwdc2023/10179/) |
| 가용성과 권한 | 시작 전 `isDeviceMotionAvailable` 확인이 필요하며 `NSMotionUsageDescription`이 없으면 motion 시작 시 앱이 충돌할 수 있음 | [CMHeadphoneMotionManager](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager?changes=latest_major) |
| 입력 연결과 탈착 | 연결 사건을 받을 수 있으며 자동 착용 감지 설정에 따라 탈착 사건과 좌우 입력 소스 변경이 발생할 수 있음 | [WWDC23 Core Motion](https://developer.apple.com/videos/play/wwdc2023/10179/) |
| 창 뒤 효과 | `NSVisualEffectView`의 behind-window blending은 창 뒤 내용을 배경으로 사용하는 효과임 | [NSVisualEffectView](https://developer.apple.com/documentation/appkit/nsvisualeffectview?changes=l_4__6) |
| 화면 캡처 | ScreenCaptureKit 문서는 화면 캡처 전 사용자 권한을 요구함 | [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit?changes=latest_be_8) |

문서의 OS 지원 시작점과 앱의 최소 지원 버전은 별개임. 모델명만으로 가용성을 확정하지 않고 실제 조합에서 확인해야 함.

## 이 사실에서 도출한 가설

고개 회전은 기준 자세와 현재 자세를 비교하는 방식이 후보임. 여기서 자세는 눈의 시선이나 화면상의 응시 지점이 아님. 부분 블러를 화면 위치와 연결하려면 화면별 기준과 각도→영역 대응을 별도로 정해야 함. 기준을 잡은 뒤 Mac·화면·사용자 위치가 바뀌면 같은 자세가 다른 의미일 수 있음.

공식 문서에서 확인한 입력은 사용자가 좌석에 있는지의 직접 측정값이 아님. 따라서 자리 이탈은 움직임의 패턴에서 추정하는 별도 문제임. 정면을 유지하며 일어나 걷기, 고개만 돌리기, 의자에서 몸을 고쳐 앉기를 구분할 수 있는지 확인 필요함. 연결 유지나 키보드 무입력만으로 이탈을 판정할 수 있다고 확정하지 않음.

화면 가림은 AppKit 창과 시각 효과가 후보임. 창 뒤 효과의 존재가 전체 데스크톱의 내용 비식별성·Spaces 대응·화면 공유 차단을 보장하지 않음. 특히 사용자 reference처럼 화면 위치마다 블러 강도가 달라지는 효과와 내용 자체의 원근 변형은 단순 창 뒤 효과와 별도로 검증해야 함. 캡처 없는 방식으로 승인된 효과가 가능한지부터 확인하고, 부족하다고 캡처 권한이나 불투명 가림으로 자동 전환하지 않음.

## 자리 이탈과 연속 블러의 가능 범위

2026-09-14 사용자 질문에 따라 공개 API와 관성 위치 추정의 한계를 추가 조사했음. 실기기 위치 추정은 아직 실행하지 않았음.

Apple의 [Core Motion 안내](https://developer.apple.com/videos/play/wwdc2023/10179/)에서 지원 헤드폰의 입력으로 확인되는 것은 자세·사용자 가속도·회전 속도임. [CMDeviceMotion](https://developer.apple.com/documentation/coremotion/cmdevicemotion)과 headphone motion의 공개 경로에서 Mac/의자에 대한 상대 위치나 거리 값을 제공하는 계약은 확인하지 못했음. `SensorLocation`은 입력이 어느 쪽 이어버드에서 오는지의 구분이며 사용자 공간 좌표가 아님.

가속도로 이동 거리를 계산하는 것은 이론적으로 가능하지만 속도·위치로 누적 계산하는 동안 센서 오차와 방향 오차도 누적됨. 중력 제거의 작은 오차도 위치 추정에 영향을 줄 수 있음. 근거는 Woodman의 [An introduction to inertial navigation](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-696.pdf), 특히 6.2.3의 오차 전파 설명임. 이 일반 원리를 적용하면 외부 기준 없이 지속적인 자리 상대 위치를 신뢰하기 어렵다는 기술적 판단이며, 해당 논문의 기기별 오차 수치를 AirPods 측정값으로 옮기지 않음.

움직임이 멎었다는 것과 원래 자리에 있다는 것도 다름. 일어난 뒤 가만히 서 있기, 의자를 뒤로 밀기, 제자리 자세 고침을 같은 동작으로 판정하지 않는지 확인해야 함. 초기 자세 보정이나 필터 조정만으로 실제 위치를 알아냈다고 주장하지 않음.

| 후보 | 연속 변화의 기준 | 현재 판정 |
| --- | --- | --- |
| AirPods 관성 위치 추정 | 추정한 좌석 상대 이동량 | 짧은 구간 실험 가능. 지속 정확도·복귀 위치·중간 정지 추적은 미검증 |
| AirPods 이탈 징후 + 부드러운 전환 | 이탈 판단 이후의 전환 진행도 | 거리 측정 없이 애니메이션 가능. 이탈 인식 정확도와 전환 지연은 별도 검증 |
| 별도 위치 근거 추가 | 추가 입력으로 확인한 위치 또는 거리 | 위치 비례가 필수일 때 조사할 대안. 특정 센서의 호환성·권한·성능은 아직 확인하지 않음 |

추천 실험은 고정된 출발점에서 자리 고침·기립·걸어 나감·중간 정지·복귀를 구별하고 사람이 확인한 실제 동작과 입력을 대조하는 것임. 짧은 구간의 위치 추정 후보가 있으면 같은 입력에서 비교함. 부드러운 전환 성공과 실제 위치 감지 성공을 별도로 보고함. 센서 추가·카메라 사용·위치 비례 제품 채택은 승인 전임.

### 걷기 감지 API — 2026-11-12 확인

이 Mac의 macOS 27 SDK에 `CMHeadphoneActivityManager`가 있으며 `API_AVAILABLE(macos(15.0))`임. 지원 헤드폰의 `CMMotionActivity`(stationary, walking, running, 신뢰도)를 받고, 헤더 설명상 자동차와 자전거는 지원하지 않음. 연결 상태(connected, disconnected) 갱신도 따로 받을 수 있음. 앱 최소 지원 버전(macOS 15)과 맞음. 터미널에서 실행한 확인 코드에서 `isActivityAvailable`과 `isStatusAvailable`이 true, 권한 상태가 허용(3)이었음. 실제 걷기 판정의 지연과 정확도, 앉아서 머리를 흔드는 동작의 오판은 실측 전임.

## 단위 1 실험안 — 승인 전

| 실험 | 입력과 관측 | 종료 시 판정 |
| --- | --- | --- |
| 입력 가용성 | 지정 모델·OS·권한 상태에서 sample 수신, 중단, 탈착·재연결·소스 교체 | 동작한 조건과 불가능/미확인 조건 분리 |
| 회전 구별 | 두 모니터 사이 회전·화면 밖 회전·작은 움직임·고개 숙임을 사람이 구분해 수행 | 정상 화면 전환과 보호 전환을 구분할 관측값·지연·오탐/누락 근거 |
| 자리 이탈 구별 | 기립·보행·정면 유지 이동·자리 고침·복귀를 구분 | 회전 실험과 별도 판정. 이탈 기준을 세울 근거가 부족하면 미해결 |
| 부분 블러·가림·복구 | 비민감 화면과 수동 각도 입력으로 영역/강도 변화, 전체 가림·해제, 화면 조합 변경 | 승인한 효과와의 일치, 가독성, 끊김·화면 누락·입력·복구 가능 여부 |

실험 시작 전 기기·화면 배치·반복 수·기록 항목·중단/복구 경로를 고정함. 원시 데이터·화면 캡처 저장은 현재 승인 없음. 실험 코드와 데이터 경로는 구조 결정 후 배치 지도에 등록함.

이 단계의 종료는 ‘어떤 조건에서 가능한지 증거가 생김’임. 구현하지 못한 기능이나 입력을 제품 지원으로 표시하지 않으며 실제 제품의 수치 합격 기준은 관측 결과와 함께 사용자에게 제안함.

## 아직 확인하지 않은 것

모니터의 물리 좌우 순서·설치 각도·사용자와의 거리, 실제 sample 주기·정확도·끊김, 장시간 drift와 부하·배터리 영향, 통화/음악/자동 기기 전환 중 입력, 부분 블러의 구현 가능 범위·가독성·성능과 화면 모드별 동작은 미확인임. 사용자 제공 reference 이미지와 설명은 확인했으며 해석은 [spec D3](spec.md#d3-어느-화면을-어떻게-가리는가)가 소유함. 원본 영상과 전환 시간은 미확인임. 이 문서에는 센서·앱·블러 실험의 통과 기록이 없음.
