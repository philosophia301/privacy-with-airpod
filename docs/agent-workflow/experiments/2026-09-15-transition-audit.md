# 전환 검사 강화의 제한 위임

메인이 감사 모듈·기존 분류 재사용·과거 로그 재분석을 소유함. Luna worker `/root/audit_tests`가 별도 파일의 합성 회귀를 작성했고, 실패 근거에 따라 혼합 비트3 인식 누락을 메인이 수정함. 이후 마지막 입력 뒤 재등장·공백2개를 같은 worker에 추가 위임함. 고정 소유권에서 확인된 구멍만 후속 위임한 운영임.

Luna `/root/audit_replay`는 남아 있는 과거 로그의 제한된 읽기 전용 탐색을 맡음. 메인도 대기 중 같은 경로를 찾았으므로 일부 중복 탐색이 생겼고 추가 조사를 중단 요청함. 비용 절감 성과로 주장하지 않음.

모델 요청은 gpt-5.6-luna, fresh 문맥, native collaboration임. fast mode를 요청하지 않았으며 runtime tier receipt는 제공되지 않음. Orca orchestration Run 실험으로 기록하지 않음. 토큰·시간 대조군은 미측정임. GUI/제스처는 모든 worker에 금지했음. 결과·검증 정본은 blur-research 문서임.

## 계측 확대와 lean 실행 후속

사용자의 결과 우선·병렬/캐시 최적화 지시로 소유권을 고정해 Luna를 사용함. `grid_capture`는 Swift 수집기, `grid_analysis`는 분석기·회귀, `cache_contracts`는 캐시 검증, `replay_fixtures`는 압축 수치 입력과 읽기 경로를 맡음. 메인은 실행기·실제 Swift 합성 픽셀 검사·통합/문서를 소유함. 초기 과제는 병렬 수행하되 수집→분석의 schema 계약과 최종 실행은 의존성 순서를 지킴.

검토 중 발견한 보정: 전환에 따른 장면 색 변화와 동적 블러 마스크를 혼동하지 않도록 지시함. 관측값의 중앙값만 비교하면 단 한 프레임의 결함이 사라지므로 프레임별 비교를 요구함. 캐시는 코드/입력/환경 변화, 실행 중 변경, Python bytecode 재사용을 구분하도록 메인이 보강함. 최대20 worker를 채우는 대신 독립 소유권4개를 사용함.

실험용 실제 GUI 작업과 캐시 재사용을 분리함. 같은 고정 입력의 fresh 병렬·fresh 순차·warm 결과를 비교하되 관측한 실행기 시간만 보고하고 모델 비용/토큰 절감으로 환산하지 않음. fast mode 요청 없음, 별도 tier receipt 없음. 실제 수치/검증은 blur-research가 소유함.

최종 회수/보정: 분석 worker 결과에 메인이 unmatched shown/부분 other셀/near-zero 기준의 거짓 성공 회귀와 GRID STATUS 처리를 추가함. 캐시 reviewer의 실행 중 ABA 변경 문제는 전후 해시 추가만으로 해결되지 않으므로 스냅샷 실행으로 대응함. 컴파일러 실체 digest와 기대 노출 수 비교도 추가함. 완료 worker에 보낸 일반 메시지는 새 작업 실행을 보장하지 않으므로 후속 구현은 `followup_task`로 시작하거나 메인이 즉시 소유해야 함. 마지막 스냅샷 검사3개는 메인이 작성했음.

최종60개+replay4건의 순차/병렬/warm 판정이 동일했음. 단회 실행기 시간은 연구 문서 참조. 같은 품질 기준으로 검증 비용을 줄인 관측이며, 자동 검사 수나 캐시 hit를 실물 제품 보장으로 환산하지 않음.
