# 자연어와 코드의 가독성

독자가 판단할 결론부터 쓰고, 필요한 구조·흐름·근거·한계를 연결함. 사실·파일·명령의 나열로 설명을 대신하지 않음.

한국어와 역할 기반 명사형 음슴체를 기본으로 함. 정의는 ‘임’, 상태는 ‘있음/없음’, 제약은 ‘필요/불가’, 관측은 ‘확인됨/미완료’, 행동은 ‘함’처럼 문장 역할에 맞춤. 식별자·경로·명령·오류는 원문을 유지함.

## 독자가 판단할 수 있게 씀

처음 등장하는 핵심 용어를 쉬운 한 문장으로 설명함. 예를 들어 보정은 사용자가 화면을 정면으로 볼 때의 자세를 기준으로 잡는 일임. 낯선 하위 시스템은 설명하되 프로그래밍 기초까지 반복하지 않음.

확정·제안·가정·실행 결과를 구분함. ‘대기’ 대신 ‘사용 기기 확인 전’, ‘실기기 검증 전’처럼 다음 행동이 보이는 상태를 씀. 원인 추정은 확인된 사실처럼 쓰지 않음.

추천에는 이유와 대안이 나은 조건을 붙임. 단점을 숨기거나 같은 결론·형식적인 칭찬·불필요한 맺음말을 반복하지 않음.

## 구조를 작게 유지함

한 문장은 한 판단을 중심으로 씀. 문장을 화면 폭에 맞춰 중간에서 끊지 않고 의미 단위로 문단을 나눔. 제목과 목록은 찾기·비교에 도움이 될 때만 사용함.

세 항목 이상의 비교·필드 대응은 표, 세 단계 이상의 흐름·상태 변화는 작은 Mermaid 또는 ASCII를 사용함. 한 문장이면 충분한 내용에는 시각화를 넣지 않음. 그래프는 실제 수치와 추세가 있을 때 사용함.

## 코드와 주석

이름과 타입으로 책임을 표현하고 함수는 한 가지 일을 맡음. 같은 정책을 여러 진입점에 복제하지 않음. 파일 약 500줄은 분리 검토 기준이며 줄 수만 줄이려고 의미 없는 파일을 만들지 않음.

주석에는 코드로 드러나지 않는 목적·불변식·함정·실패 결과만 남김. 진행 이력과 규칙 전문은 주석에 복사하지 않음. 테스트 이름은 ‘조건에서 어떤 결과가 발생한다’처럼 실제 assertion의 범위를 말함.

## 정본과 검토

소유권은 [배치 지도](../../AGENTS.md#배치-지도)를 따름. 같은 승인·수치의 사본을 만들지 않음. 확정한 과거 실험 기록은 보존하고 새 관측·정정으로 연결함.

완료 전 목적·현재 상태·다음 행동, 상대 링크·anchor, 표·코드 블록, 공백, 미정과 승인 표시를 확인함. 예정 경로와 실행하지 않은 명령을 현재 사용법처럼 쓰지 않음. 문서 검사는 의미·제품 행동의 증거를 대신하지 않음.
