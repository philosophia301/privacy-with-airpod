# 테스트 품질과 검증 수준

테스트는 사용자나 협력 코드가 의존하는 행동을 보호해야 함. 이름·파일·개수·coverage만으로 품질이나 실제 AirPods 동작을 증명하지 않음.

## 추가하기 전에 확인함

- 어떤 조건에서 어떤 결과를 관측하며, 기존 검사가 놓치는 실제 결함은 무엇인지 설명 가능해야 함.
- 기대값은 spec·알려진 입력·독립적인 성질에서 정함. 검사 대상의 알고리즘을 복사해 정답을 만들지 않음.
- 잘못된 구현에서 실제로 결과가 달라지는 입력과 assertion을 사용함. 빈 목록 순회, 기다리지 않은 비동기 assertion, 다른 오류로 먼저 실패하는 검사를 피함.
- 내부 함수 분리·호출 순서를 바꿔도 같은 계약이면 유지돼야 함. 호출 자체가 금지·자원 해제 등의 계약일 때는 호출 검증 가능함.
- 시계·입력·외부 상태를 통제하고 실패해도 자원을 정리함. sleep 증가·retry로 간헐 실패를 숨기지 않음.
- 테스트 이름의 조건과 결과를 assertion이 실제로 확인해야 함. 센서 대역에 숫자를 넣은 검사를 ‘AirPods 감지 성공’이라고 부르지 않음.

중요한 검사는 예상 결함을 넣었을 때 계약 위반 때문에 실패하는지 확인할 수 있음. 모든 테스트에 변이 도구를 추가할 필요는 없음. 버그 수정에는 그 버그를 잡는 회귀 검사를 남김.

## 이 앱에서 구분할 경계

아래는 검증 설계 기준이며 테스트 target이나 명령이 이미 있다는 뜻은 아님.

| 수준 | 관측할 것 | 증명하지 못하는 것 |
| --- | --- | --- |
| Unit | 통제한 자세·시각·연결 사건에 대한 승인된 상태 전환 | 실제 센서 품질·OS 화면 가림 |
| Integration | 실제 앱 구성요소 간 전달, 권한·오류·취소·정리 연결 | 대체한 AirPods와 사람이 보는 화면 |
| macOS UI·system | 실행 앱의 조작·가림·복구와 OS 창 동작 | 합성 입력이면 실제 머리 움직임 감지 |
| 실기기 acceptance | 명시한 Mac·AirPods에서 회전·이탈·복귀의 전체 결과 | 다른 모델·OS·환경 전체의 보장 |

대역은 경계 입력과 결과만 제공하며 제품 판정 규칙을 다시 구현하지 않음. 같은 계약의 대역은 한 곳이 소유하고 외부 SDK 대역은 해당 검증 경계 가까이에 둠. 실제 테스트 경로는 앱 구조를 정할 때 AGENTS 지도에 등록함.

## 실패 비용에 맞춰 조건을 고름

| 위험 | 필요한 관측의 예 |
| --- | --- |
| 시간·각도 경계 | 승인된 경계의 직전·동일·직후, 회전 중 짧은 복귀와 반복 흔들림 |
| 센서 신뢰성 | 오래된 sample·무응답·오류·재연결·좌우 소스 교체에 대한 결과 |
| 잘못된 해제 | 과거 callback이나 단순 재연결이 가린 화면을 임의로 열지 않는지 |
| 권한·중단 | 거절·철회·잠자기·앱 종료에서 실제 상태와 안내가 일치하는지 |
| 화면 조립 | 지원하는 화면 수·Spaces·전체 화면·화면 추가/제거에서 가림과 복구 |
| 감지 품질 | 회전·자리 이탈의 누락과 정상 타이핑·고개 숙임·자세 고침의 오탐을 구분 |

예시를 미승인 제품 정책으로 사용하지 않음. 해당 행동의 spec을 확정한 뒤 예상 결과를 채움.

## 실행과 보고

변경된 계약을 잡는 가장 작은 검사부터 실행하고 필요한 실제 연결 검사를 포함함. 검사 실행자는 판본·명령·종료 코드·관측·대역·미관측을 제출함. 같은 판본의 신뢰할 수 있는 결과가 있으면 이유 없이 전체를 다시 실행하지 않으며 코드 변경·실패·검증 공백이 생기면 재실행함.

실물 검증은 AirPods 모델·macOS·화면 배치·입력 조건·반복 횟수·지연·오탐·미탐을 남김. 통과 수치와 허용치는 사용자 결정 전까지 목표 제안으로 표시함. 화면 내용이나 센서 기록을 수집·보관하는 정책은 별도 승인 경계를 따름.

문서만 바뀐 Phase에는 앱 테스트를 만들지 않음. 현재 실행 가능한 검증 안내는 [AGENTS](../../AGENTS.md#현재-검증)가 소유함.
